# Admin Operations Workspace — Two-Loop Refinement Record

## Loop One: Workflow Safety, Copy Clarity, and Operational Hierarchy

The first review focused on reducing ambiguity before a public practice change. The workspace now leads with a protected preview, followed by a campaign matrix and grouped video routes, then the complete Page Index and individual practice cards. This places review and impact context before publishing controls.

The configuration store distinguishes **live**, **draft**, and **history** records. Publishing a practice configuration or a reviewed draft creates a protected restore point. Bulk visibility operations require the exact confirmation term `APPLY`; restoring a saved version requires `RESTORE`.

Profile prompts were refined so they distinguish safe defaults from actual review actions. In particular, an approved portrait now requires meaningful alt text for readiness; pending portraits explicitly remain behind the neutral placeholder. The workspace only reports aggregate general BBT inquiry counts and states clearly that practice GoHighLevel survey activity remains in GoHighLevel.

## Loop Two: Responsive Usability, Edge Cases, and Release Readiness

The second review verified desktop, phone-width, and reduced-motion review modes. The preview changes its embedded viewport without navigating away from the protected workspace, and the reduced-motion option requests the poster-first state for landing-page review.

The Page Index search, practice filter, category filter, and video-only filter were checked against the complete route inventory. Profile validation rejects non-local portrait URLs, and a direct live publication now clears any older saved draft for the same practice so the review state cannot become misleading. Bulk changes remain constrained to display settings and require explicit scope confirmation.
